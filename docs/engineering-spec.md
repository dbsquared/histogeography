# Engineering Spec: 中国及周边地区 SRTM DEM 数据获取与地形渲染系统

## 项目概述

从地理空间数据云（GSCloud）平台获取覆盖中国及周边地区的 SRTM 90M 数字高程模型数据，并构建一套可复用的地形图渲染管线，将原始 `.img` 栅格文件转化为包含高程色阶、山体阴影和等高线的可视化地形图。

## 背景

项目启动前，团队对 GSCloud 平台的数据产品、文件格式、下载机制和命名规则均不了解。WebFetch 工具获取的数据页面受前端渲染限制（分页参数不生效），无法直接遍历全部 872 条 SRTM 记录。下载链接包含临时会话令牌（`sid`），无公开 API 文档。原始 `.img` 文件经检测为 ZIP 压缩包（magic bytes: `PK\x03\x04`），内部嵌套真实 ERDAS Imagine 格式栅格文件。

## 组件 1: 数据下载器 — `download_srtm_china.py`

### 职责

从 GSCloud 批量下载中国及周边地区的 SRTM 90M DEM 瓦片。

### 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--sid` | string | 是 | 会话认证令牌，从手动触发的下载请求中获取 |
| `--uid` | string | 是 | 用户 ID |
| `--output-dir` | string | 否 | 输出目录，默认 `srtm_china_data` |
| `--start-from` | string | 否 | 从指定文件名开始续传 |
| `--skip-existing` | flag | 否 | 跳过已存在的文件 |

### 文件名生成逻辑

SRTM 文件命名遵循 `srtm_{XX}_{YY}` 模式，其中条带号和行编号与地理坐标的映射关系：

```
经度 = -57.5 + (条带号 - 25) × 5
纬度 = 52.5  - (行编号 - 2)  × 5
```

中国及周边区域的坐标范围和对应文件名：

| 维度 | 地理范围 | 文件名参数 | 取值范围 | 文件数 |
|------|----------|-----------|---------|--------|
| 经度 | 73°E ~ 135°E | 条带号 | 52 ~ 64 | 13 |
| 纬度 | 18°N ~ 54°N | 行编号 | 02 ~ 09 | 8 |

总计：13 × 8 = **104 个文件**。

### 下载 URL 模板

```
https://bjdl.gscloud.cn/sources/download/305/{filename}?sid={session_token}&uid={user_id}
```

其中 `305` 为数据集标识（SRTMDEM 90M 分辨率原始高程数据），`{filename}` 格式为 `srtm_XX_YY`。

### 关键约束

- `sid` 令牌具有时效性（数分钟到数小时），过期后返回 401/403
- 下载请求不需要特殊 Header，只需 URL 中的 query 参数
- 脚本实现了指数退避重试（最多 3 次），以及基于文件大小校验的完整性验证

### 依赖

- Python 3.6+
- `requests`
- `tqdm`

## 组件 2: 地形渲染器 — `terrain_renderer.py`

### 职责

将原始 `.img` 栅格数据渲染为包含地形信息的可视化 PNG 图像。

### 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| 位置参数 `file` | string | 与 `--mosaic`/`--batch` 三选一 | — | 单个 .img 文件路径 |
| `--mosaic` | string | 三选一 | — | 拼合目录中的多个瓦片 |
| `--batch` | string | 三选一 | — | 批量渲染目录中的所有文件 |
| `--mode` | enum | 否 | `all` | 渲染模式 |
| `--output` | string | 否 | 自动生成 | 输出文件路径 |
| `--dpi` | int | 否 | 200 | 输出分辨率 |
| `--azimuth` | float | 否 | 315 | 光源方位角（度） |
| `--altitude` | float | 否 | 45 | 光源高度角（度） |
| `--z-factor` | float | 否 | 1 | 高程放大因子 |
| `--contour-interval` | float | 否 | 200 | 等高线间距（米） |
| `--hillshade-alpha` | float | 否 | 0.5 | 阴影层透明度 |
| `--contour-alpha` | float | 否 | 0.4 | 等高线透明度 |
| `--vmin` | float | 否 | 自动 | 最小高程值 |
| `--vmax` | float | 否 | 自动 | 最大高程值 |
| `--bounds` | 4×float | 否 | — | 裁剪范围 (min_lon max_lon min_lat max_lat) |
| `--downsample` | int | 否 | 1 | 下采样因子 |
| `--figsize` | 2×float | 否 | 自动 | 图像尺寸（英寸） |

### 渲染模式

| 模式 | 图层组成 | 适用场景 |
|------|---------|---------|
| `elevation` | 高程色阶 | 快速概览地势高低 |
| `hillshade` | 山体阴影 | 地形立体感、地质构造识别 |
| `contour` | 阴影底图 + 等高线 | 地形测绘、路径规划 |
| `elevation+hillshade` | 高程 + 阴影叠加 | 地理科普、报告插图 |
| `elevation+contour` | 高程 + 等高线 | 学术地图、工程用图 |
| `all` | 高程 + 阴影 + 等高线 | 完整地形信息展示 |

### 渲染管线

```
.img 文件
    │
    ▼
ZIP 检测 (magic bytes: PK\x03\x04)
    │
    ├── 是 ZIP → 解压到临时目录 → 获取内部 .img/.tif
    │
    └── 非 ZIP → 直接使用
    │
    ▼
rasterio 读取栅格数据 → float32 数组
    │
    ▼
无效值处理 (nodata, -32768, <-1000, >9000 → NaN)
    │
    ▼
┌──────┬───────┬──────────┐
│ 高程  │ 阴影   │ 等高线    │
│ 色阶  │ 计算   │ 绘制      │
└──┬───┴───┬───┴────┬─────┘
   │       │        │
   └───────┴────────┘
           │
           ▼
   图层叠加 (alpha blending)
           │
           ▼
   地图元素 (标题/坐标轴/色阶条/网格/来源标注)
           │
           ▼
   PNG 输出 (matplotlib Agg 后端)
```

| 0.08 | `#b3d9a0` | 低地 |
| 0.15 | `#8cc579` | 平原 |
| 0.25 | `#6ba356` | 丘陵 |
| 0.35 | `#c9b458` | 低山 |
| 0.45 | `#c9a048` | 中山 |
| 0.55 | `#a67c3d` | 高山 |
| 0.65 | `#8b5e2f` | 高原 |
| 0.75 | `#9e7a6a` | 极高山 |

### 山体阴影算法

Hillshade 计算分块执行（`block_size = 2000` 行），使用 float32 精度，避免一次性分配全幅临时数组：

```
hillshade = cos(altitude) × cos(slope)
          + sin(altitude) × sin(slope) × cos(azimuth - aspect)
```

其中 `slope` 和 `aspect` 由 `np.gradient` 计算的 dx/dy 推导。输出归一化到 0~255 uint8。

### 等高线绘制

- 主要等高线：按 `--contour-interval` 间距均匀分布
- 加粗等高线：每 5 条加粗一次（线宽 × 2.5）
- 颜色：`#4a3728`（深褐色）
- NaN 区域自动跳过

### ZIP 格式自动解压

GSCloud 下载的 `.img` 文件经检测为 ZIP 压缩包（magic bytes: `PK\x03\x04`），内部包含真实 ERDAS Imagine 格式栅格文件。处理流程：

1. 读取文件头 4 字节
2. 前两字节为 `PK` 则判定为 ZIP
3. 使用 Python `zipfile` 解压到临时目录（每个 ZIP 独立子目录，避免同名文件冲突）
4. 通过 `rasterio` 读取解压后的栅格文件
5. 完成后清理临时目录

### 中文字体适配

渲染器在初始化时遍历 matplotlib 字体管理器，按优先级匹配系统中文

字体：Microsoft YaHei → SimHei → SimSun → Noto Sans CJK SC 等。匹配成功后设置 `plt.rcParams['font.sans-serif']`，解决中文标注（坐标轴标签"经度""纬度"、数据来源声明等）的方块字问题。同时关闭 `axes.unicode_minus` 避免负号渲染异常。

### 拼合模式

当 `--mosaic` 传入目录路径时：

1. 扫描目录中所有 `.img` 文件
2. 对 ZIP 格式文件逐一解压到独立临时子目录
3. `downsample = 1`：使用 `rasterio.merge.merge()` 直接拼合
4. `downsample > 1`：逐文件读取 → 均值下采样 → 手动计算全局范围 → 逐瓦片写入拼合数组
5. 如指定 `--bounds`，在拼合结果上按经纬度裁剪
6. 传递拼合后的数组到渲染管线

### 内存管理策略

| 场景 | 策略 |
|------|------|
| 单瓦片渲染 | 默认即可（6000×6000 float32 ≈ 137MB） |
| 多瓦片拼合 | 使用 `--downsample` 降低输入分辨率 |
| Hillshade 计算 | 分块处理（2000 行/块），避免分配全幅 gradient 数组 |
| 全局拼合数组 | float32 + NaN 标记，由 numpy 管理连续内存 |

## 数据格式

### SRTM 90M DEM 文件属性

| 属性 | 值 |
|------|-----|
| 数据来源 | GSCloud 数据集 ID 305 |
| 空间分辨率 | 约 90 米/像素 |
| 投影 | 经纬度/WGS84（原始），UTM/WGS84（部分衍生产品） |
| 数据类型 | 16 位有符号整数 (Int16) |
| 无效值 | -32768 |
| 单个瓦片覆盖范围 | 5° × 5°（约 6000 × 6000 像素） |
| 单个瓦片文件大小 | 约 30~40 MB（ZIP 压缩后） |

### 无效值处理

渲染管线将以下值标记为 NaN：

- `src.nodata`（从栅格元数据读取）
- `-32768`（SRTM 标准无效值）
- `< -1000`（不可能的高程）
- `> 9000`（不可能的高程，排除珠穆朗玛峰 8848m 以上的数据错误）

### 环境限制

测试环境受限于磁盘空间和内存，拼合渲染大区域时遇到两个瓶颈：

1. **磁盘**：100 个 ZIP 文件解压临时拷贝消耗约 3.5 GB 空间，环境可用空间不足
2. **内存**：10800×9600 的 hillshade 计算需要约 800 MB 连续内存，PNG 编码需要额外空间

生产环境中建议至少 16 GB 内存和 10 GB 可用磁盘空间用于拼合渲染。

## 数据完整性校验（2026-06-30 实测）

对 `srtm_china_data/` 目录进行实测，结果如下：

| 类别 | 数量 | 说明 |
|------|------|------|
| 已下载·有效（陆地） | 92 | 标准尺寸 6000×6000，含正常陆地数据 |
| 已下载·有效（海区稀疏） | 7 | 体积 16~473KB，尺寸完整 6000×6000，有效像素 0.00%~1.61%，覆盖海区 |
| 已下载·损坏 | 1 | `srtm_55_04.img` 下载截断（17.3MB/应~31MB），ZIP 头完好但缺 EOCD → 全境渲染图左上方灰色空洞 |
| 缺失 | 4 | `srtm_62_09`、`srtm_63_09`、`srtm_64_07`、`srtm_64_09`，均为东部海区边缘瓦片 |
| 总计 | 100/104 | 2.5 GB |

7 个海区稀疏文件经 rasterio 逐一校验，全部为有效 ZIP（含标准 6000×6000 栅格、EPSG:4326、bounds 正确），仅因覆盖海洋区域导致有效像素极少、压缩后体积小。**均非截断或损坏**。

`srtm_55_04.img`（90-95°E / 40-45°N，新疆东部）经全量 ZIP 完整性扫描发现损坏：文件头 `PK\x03\x04` 完好但缺少 ZIP 中央目录结尾（EOCD），文件仅 17.3 MB（同系列正常约 31 MB），系下载中途截断。mosaic 拼合时该瓦片解压失败被跳过，对应位置变为 NaN，在 `china_full_terrain.png` 左上方（约 23% 宽、25% 高处）形成灰色空洞。需重新下载修复。

结论：对中国陆地地形渲染而言，数据集已**实质完整**（99/100 有效）。1 个损坏瓦片需重新下载，4 个缺失瓦片为菲律宾海/太平洋海区，对陆地渲染无实质影响。

## 组件 3: 江河+湖泊覆盖图层生成器 — `river_overlay.py`

### 职责

在 `china_full_v3.png` 地形底图上叠加 Natural Earth 河流和湖泊矢量数据，生成带中文标注的覆盖图层。

### 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| 底图 PNG | file | 是 | `china_full_v3.png` | 地形渲染底图 |
| 河流 GeoJSON | file | 是 | `data/rivers/ne_10m_rivers.geojson` | Natural Earth 10m 河流 |
| 湖泊 SHP | file | 是 | `data/lakes/ne_10m_lakes.shp` | Natural Earth 10m 湖泊 |

### 输出

| 文件 | 说明 |
|------|------|
| `rendered/china_rivers_lakes_overlay.png` | 地形+河流+湖泊合成图（RGB） |
| `rendered/china_rivers_lakes_overlay_layer.png` | 透明覆盖图层（RGBA），可独立叠加 |
| `rendered/china_rivers_overlay.png` | 仅河流的合成图（向后兼容） |

### 技术细节

- 使用 PIL 直接绘制，无 matplotlib 依赖，支持 15600×9600 大图
- 河流线宽：主要 14px / 命名支流 9px / 其他 5px
- 湖泊：半透明蓝填充 (alpha=90) + 深蓝轮廓，标注 scalerank<=4 的湖泊
- 中文标签：微软雅黑粗体，河流 72px，湖泊 48px，半透明背景+描边
- 高程色标条：右侧 260px 宽，14 级 terrain_custom 色阶，0–8800m 刻度
- 已知问题：湖泊标注含跨国湖泊（巴尔喀什湖、贝加尔湖等），待加中国境内过滤
